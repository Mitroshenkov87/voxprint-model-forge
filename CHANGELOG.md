# Changelog

## Unreleased

- Z-Image is the default LoRA base for a new project (`--base z-image`, registry id `z-image`, short tag `zimg6b`). MOSS-Image SFT stays an optional base (`--base moss`, registry id `moss-image-base`, short tag `moss5b`, weights `OpenMOSS-Team/MOSS-Image-SFT` @ `fc5de0d5`). A project or a LoRA file with no base recorded is still Z-Image, including older filenames and sidecars. `VOXPRINT_FORGE_MOSS_LORA=0` hides MOSS; `VOXPRINT_FORGE_ZIMAGE_LORA=0` hides Z-Image. An omitted `lora train --base` follows the project's first base, so an existing MOSS project stays on MOSS.
- Vendored `voxprint-common` 0.7.0 (`vendor/voxprint_common-0.7.0-py3-none-any.whl`, sha256 `582ed667ef51896086b6f70c85148c525ea24b5c3dacb64f546a76486d311eca`, Components local commit 241ac452, not yet pushed). The bundled model-index pin is now serial 10 (unsigned), head `15edeab0f7a874c27d2b38ef6ecb69106ff94df8`, sha256 `dab444f7d820b2611cb2aa1ec00ad8241a1ae41a4c68823aff793bfa0a72ce0e`. That pin marks Z-Image-Turbo as the default catalog entry (revision `a853c26eb946b9010b4bd142a2ad1439d83e7896` on `Mitroshenkov87/voxprint-mirror-z-image-turbo`, descriptor sha256 `fefa994cbef9d62201089f61d0bde2914ba0e826650f323816ec9b562965168e`, 11,047 B) and full Z-Image, `moss-image-base` and `moss-image-sft` as optional. The old `mirror-z-image-turbo` index row is retired.
- App model list: `z-image-turbo` is required (generation default). Full Z-Image (`z-image` @ `04cc4abb`, the LoRA training base) and MOSS are optional. Signed model index serial 11 (same head `15edeab0f7a874c27d2b38ef6ecb69106ff94df8`) is at `signed-index/index.json` and `signed-index/index.json.sig`. The bundled pin and the previous signed index were both serial 10 with identical model rows, including Z-Image-Turbo as default; Forge `check_index` / `next_serial` require a published serial strictly above the bundled pin, so the index was re-signed as serial 11. `tools/sign_model_index.py` built it from the Components handover, dropped the retired `mirror-z-image-turbo` row, and refuses to sign while any `TODO` remains. `tools/check_model_index.py` no longer maps `z-image-turbo` to the retired id.
- Z-Image file lists in `mdl.json` and `app-models.json` include the mirrored sidecar paths `.gitattributes`, `README.md`, and `teaser.jpg` from the 0.7.0 handover.
- LoRA safetensors headers carry `voxprint.lora.trained_base` (`z-image@04cc4abb` or `moss-image-base@<pin>`) and `voxprint.lora.compatible_bases` (JSON `["z-image","z-image-turbo"]` or `["moss-image-base"]`). Legacy `voxprint.lora.base` and the `zimg6b` / `moss5b` file tags are unchanged. A Z-Image LoRA is accepted on Z-Image-Turbo; base-to-Turbo strength and likeness are unmeasured. Fine-tuning Z-Image-Turbo is not offered.
- Z-Image 16 GB LoRA recipe (release path): `--vram 16` stores the DiT as FP8. Presets stay `quick` (fast smoke test: 150 steps, rank 16, 768 px), `balanced` (recommended: 1500 steps, rank 32, 1024 px, lr 1e-4), and `best` (quality: 3000 steps, rank 32, 1024 px, lr 8e-5). Planned peak reserved is about 9.03 GiB (`quick`) and 10.08 GiB (`balanced`/`best`); `vram_need_gb` is 10.0 and 11.1 including 1 GiB headroom. Step time on the 16 GB tier is the measured 9.7 s/step at 1024 px, batch 1, accum 1 (RTX 4090 laptop); `balanced`/`best` use accum 2, so the estimator scales that to 19.4 s/step. The reserved peak itself is unmeasured. The 24 GB Z-Image time (1.6 s/step) and peak are unmeasured; the 24 GB plan is about 14.87 GiB (`quick`) and 16.27 GiB (`balanced`/`best`).
- `lora prepare --base moss|z-image|both` (default `z-image`) stores `bases` on the project. `both` is Z-Image, then moss. Crops and captions stay base-free. `lora train --base both` trains one base, releases its encoders, then trains the next. A project with `bases` keeps checkpoints and exports under `checkpoints/<base>/` and `export/<base>/`. A project without that list keeps those folders at the project root.
- New exports are named `<id>.moss5b.safetensors` and `<name>.moss5b.voxlora` (`zimg6b` for Z-Image). The safetensors header carries `voxprint.lora.base`, `base_family`, `base_variant` (`sft`, `base`, or `z-image`), `base_sha256` and `dataset_id`. A stored variant wins; `moss-image-base` with none recorded is `sft`; a file with no base is `z-image`. The `voxprint-model.json` sidecar carries `base` (`mdl_id`, `revision`, `sha256`, `mirror`) and `compatible_bases`. A loader that is asked for the other base raises `lora.err.base_mismatch`.
- `lora retrain --base moss|z-image PROJECT` adds that base to the project and trains on the prepared photos already there. Weights are not converted. `--dry-run` prints the plan and leaves the project unchanged. The base-mismatch error names this command as the fix (`forge lora retrain --base moss|z-image PROJECT`).
- `forge moss-prequant` builds `voxprint-moss-image-sft-compact` from a local MOSS-Image SFT snapshot and the resharded Qwen3.5-9B encoder (fp8, int8 or nf4). The default peak budget is 13.5 GB (allowed 13–14). MOSS-Image Base is not a default target. It does not download. It is not run in this tree; measuring it waits on a GPU.
- `forge moss-prequant` streams each safetensors shard on CPU and quantizes one layer group at a time (meta skeleton, no `caching_allocator_warmup`), so a 13.5 GB cap never sees a single ~16 GB bf16 allocation of the Qwen3.5-9B encoder.
- `forge moss-peak --mode gen|train|both` measures peak VRAM and process RSS on a local `voxprint-moss-image-sft-compact` build. It loads the build read-only, checks sha256 sidecars, and attaches a seeded dummy LoRA in memory. Generation discards the image. Training runs a few AdamW steps (default 5) on synthetic latents and a fixed caption, and saves nothing: no checkpoint, no LoRA file, no optimizer state. The JSON report is refused when it would land inside the build or another model directory. It does not download. It is not run in this tree; measuring it waits on a GPU.
- `scripts/test-offline.sh` runs pytest inside `unshare -rn` with loopback up and no default route. A normal pytest run does not change network settings.
- Saved pictures default to WebP: lossless for masters, series and hand-offs, lossy quality 90 for regular pictures. PNG, JPEG and AVIF stay available. Prompt, seed, steps, base, LoRA and sha256 are left out of the file unless `--embed-metadata` is set. The app setting defaults to off.
- `lora prepare` photo I/O uses less memory: each photo is read from disk once (the photo id is hashed from the same bytes it is decoded from), decoded without extra full-size copies, and blur and duplicate checks share one grey copy. Kept photos are held as file bytes, not as decoded pixels. The PNG writes run on up to 4 threads, with results taken in input order. Prepared files, captions, `drops.jsonl` and `gate_trace.jsonl` are byte-identical to before, and the checks, the safety check and which photos are kept are unchanged. `scripts/bench_prepare_io.py` measures it. The Photos step's check and the Simple-mode count scan use the same single-read decode.
- `lora prepare` runs in phases: safety check with only the judge and age estimator loaded, a full unload (also when the check is interrupted), then the captioner. Photos are decoded one at a time per phase instead of all held decoded, which cuts peak RAM on large sets (`scripts/bench_prepare.py` measures it with CPU stand-in models). Each photo is cropped once (the caption uses the same crop that is written). Decisions, `gate_trace.jsonl`, `drops.jsonl`, captions and prepared PNGs are unchanged.
- `lora eval PROJECT [--step N|all] [--images DIR]`: likeness score with OpenCV YuNet + SFace (new optional MDL id `sface-2021dec`). Reference is the mean embedding of the kept training photos; the report gives each picture's cosine, mean, median, `n`, pictures with no face, and the training photos' own leave-one-out baseline. fail below 0.363, warn below 0.50 or below 0.6 x baseline. Written to `eval/likeness.jsonl`, `eval/report.json`/`report.md`, and `likeness` in `voxprint-model.json`. `lora finish` scores its final previews before export. Quality score only: it never blocks export and does not touch the safety check.
- Training previews without `--preview-prompts` show the subject: for a person, `<trigger> woman, head-and-shoulders portrait, face clearly visible, looking at camera` (kind-aware). `lora finish` draws this prompt first; a straight-through run no longer draws its final preview from an empty prompt.
- Preview PNGs record `voxprint.seed`, `voxprint.lora_scale`, `voxprint.base_model`, `voxprint.lora_sha256` and `voxprint.step` as PNG text.

- `lora finish` after training uses the base stored on the project. A straight-through run (`--review-rounds 0`) no longer exits 2 with the base reported missing. If that base is not on disk, finish fetches it with MDL before the final preview. CLI errors name `voxprint-forge-cli models fetch` (or `accounts add` for upload tokens) instead of a window in the app.
- `lora train --fetch-missing` now also fetches the selected training base (for example `--base z-image`, or the base the project recorded) when it is not installed; previously only the required gate models were fetched and the run exited 2 with `lora.err.base_missing`. `lora retrain` and `lora extend` share the same path. `--no-fetch` and `--dry-run` still fetch nothing.
- `lora prepare` appends each safety-check trace row and each safety drop as soon as the photo is decided, and writes `gate_run.json`. Training does not start while that run is `running` or `interrupted`; run prepare again. A photo with no trace row was not checked and is not set aside.
- `lora finish` on a straight-through run no longer leaves the project waiting in review when the checkpoint is missing or finish fails or is interrupted. Finish now builds the review state in memory and writes it to `review/state.json` only once the LoRA is saved, so `lora train` and `lora continue` still work afterwards. A missing checkpoint is now reported before finish fetches the base model.
- `lora prepare`: large single photos (for example 4500x3000 portraits) are no longer set aside as `lora.drop.collage`. Long straight edges inside one photo, such as a person against a backdrop or a floor line, were read as panel seams. Grids and side-by-side collages, with or without gutters, are still set aside.
- `lora prepare --keep FILE` (repeatable) keeps a photo that would be set aside as a collage or a near-duplicate. The photo still goes through every other check, the safety check included. docs/LORA.md and `--help` describe it.
- `lora prepare` keeps near-duplicate photos by default. A warning names the photo and the earlier photo it resembles. `--drop-near-duplicates` sets them aside as `lora.drop.duplicate` as before, and `--keep FILE` overrides that for one photo. A byte-identical copy of a photo is still skipped.
- `lora prepare`: captions describe attire as it appears. Unclothed subjects were sometimes described as wearing lingerie. Qwen3-VL's description prompts never asked about attire, and the separate unclothed answer never reached the caption text, so the model chose its own wording. Both description prompts now ask for the clothing as worn, or a plain neutral word (unclothed, nude, topless) when there is none, and ask the model not to name clothing that is not in the photo. Caption text is stored unchanged. The stored `unclothed` flag is now also true when the caption text says unclothed.
- `lora finish`: fixed "Expected all tensors to be on the same device, cuda:0 vs cpu" in the final preview. The preview loaded the base and the LoRA but never moved the transformer to the card (the adapters keep it on the CPU until the encoders are released), so the VAE and the prompt embeddings were on `cuda:0` and the transformer with its LoRA on the CPU. The final preview now follows the training order (encoders, prompts, encoders off, transformer and LoRA onto the card) and checks that the model is on one device first. `lora finish` also writes the `.voxlora` to `<project>/export/`. `--no-preview` skips the preview. A preview that fails prints `lora.warn.final_preview` and still finishes and exports the LoRA.
- `lora train` / `lora continue`: when a run pauses for review and stdin is not a terminal, a hint on stderr lists `lora review`, `lora continue` and `lora finish`, and `--review-rounds 0` for unattended runs. The GUI is unchanged.
- `--sample-framing {mixed,portrait}` on `lora train` and `lora continue` (stored as `sample_framing`). `portrait` draws every review sample as a face close-up for judging likeness. The default `mixed` is the old rotation. `lora continue` also takes `--sample-attire`.
- Docs and help: use `--preset balanced` for a person LoRA; `quick` is a smoke test (RTX 4090 person run: quick 120 steps 1.68/5 likeness, balanced 1000 steps 3.95/5). Only the exported `.voxlora` is the deliverable; `checkpoints/step-*.safetensors` are intermediate and Canvas does not accept them.
- lora gate: primary-face selection (gate.json v-bump).
- `lora prepare`: `drops.jsonl` has one line per set-aside photo. A re-run on the same project no longer appends a second copy of earlier lines.
- Windows setup: adds `{app}\venv\Scripts` (`voxprint-forge-cli.exe`) to the current user's `Path` once, and the uninstaller removes only that entry. The old RU guide shortcut is now removed by an ASCII pattern.
- `preflight` and the other plan commands work on an installed copy without a checkout: the default plan ships in the package (`voxprint_forge/data/plan.toml`, kept equal to `plans/plan.toml` by a test). A checkout's `plans/plan.toml` and an explicit `--plan` still take precedence.
- `lora prepare --help` explains `--name` and `--consent-method` and shows an example. A missing `--name` prints one line with an example, `--name Garnis_AI --consent-method verbal` (still exit 2). docs/LORA.md documents `--name`, `--consent-method` and `--fetch-missing`.
- `opencv-python-headless==5.0.0.93` and `timm==0.8.13.dev0` are now core package dependencies (the LoRA safety gate needs them). Linux from-source install: `installer/linux/install.sh` installs the `[gui]` extra, the pinned MiVOLO package (commit `37475e3f8818b5f22448003feec3e64b01bfb188`, `--no-deps --no-build-isolation`, `setuptools<81`), and writes `~/.local/share/applications/voxprint-model-forge.desktop` with the app icon. When the age estimator does not load because those packages are missing, `lora prepare`/refset fail closed with `lora.err.gate_missing_deps`, which names that install command instead of the misleading "Prepare the photos first".
- App: the "Extend the set from samples" switch on the Photos step, the overflow-menu "Add more photos to a model…" action and the result-step "Add more photos" button are hidden for now; the implementation stays behind `EXTEND_FROM_SAMPLES_ENABLED = False` in `voxprint_forge.app.window` and comes back later as its own task. The `lora extend` and `lora refset` commands are unchanged.
