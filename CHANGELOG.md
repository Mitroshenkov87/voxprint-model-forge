# Changelog

## Unreleased

- Size-aware safety-check batches in `lora prepare`: kept photos are split by decoded size into light (up to 1280x1280 px), medium and heavy (12 MP and up) classes, checked in chunks of the VRAM-tier batch, half of it and a quarter of it (never below 1), so a heavy photo no longer pads a big batch. Chunks run in order of their first photo and `gate_trace.jsonl`, `drops.jsonl`, the photo ids and every gate input keep the sorted file-name order, so the age-flag 10 % share picks the same photos as before. Progress sends one `prepare.safety` event per chunk with the percent and ETA weighted by photo size (`Progress.emit(work_done=, work_total=)`), so the estimate no longer jumps when a batch lands (for example "About 1 min left" at photo 16 and "About 4 min left" at 17). stderr gains `prepare: check chunks N (light a, medium b, heavy c photos)`. The age estimator's temporary frame is lossless WebP too (PNG only for a side over the 16383 px WebP limit).
- Prepared training crops are written as lossless WebP (`prepared/{id}.webp`): the same pixels as PNG in smaller files with a faster encode (method 0 / quality 25: 3-5x faster to encode than PNG and 19-28% smaller on 1024 px photo crops; decoding is about as fast), through the new `imageio_save.save_lossless_webp`. Other picture writes are WebP too, including the MoSS fit/prequant bench pictures. Older projects with PNG crops keep loading: the prepare reader falls back to the legacy `.png` file of the same id.
- Third-party warning floods print once per process and the CUDA allocator's OOM retry noise stays hidden. `transformers.processing_utils` ("Kwargs passed to `processor.__call__` have to be in `processor_kwargs`", logged on every processor call that still passes processing kwargs through `**kwargs`) joins the existing at-most-once filters (bitsandbytes `MatMul8bitLt` casts, `MatmulLtState` deprecation `FutureWarning`s) in `voxprint_forge.quiet_warnings`. The CLI also defaults `TORCH_CPP_LOG_LEVEL` to `ERROR` (`os.environ.setdefault`, so a user-set value wins) at import, before torch loads, which silences the native `c10/cuda/CUDACachingAllocator.cpp` line `memory allocation failed with OOM ... while trying to allocate ...` that torch 2.14 logs on every failed `cudaMalloc`, including attempts the release-and-retry path recovers. C++ `LOG(ERROR)`/fatal messages still print, Python exceptions (including `torch.OutOfMemoryError`) and the allocator retries are unaffected, and `TORCH_WARN` from Python-called ops still reach the `warnings` module.
- LoRA age gate on attested-adult person sets (final rule, 2026-11-18): a photo MiVOLO finds no face in is never dropped by the age gate (`keep_reason` `kept_no_face`, at any no-face ratio), and MiVOLO-only under-age flags the judge does not share are kept as false positives up to `floor(AGE_FLAG_KEEP_SHARE * input photos)` (`AGE_FLAG_KEEP_SHARE = 0.10`: 18 of 180, 0 of 9), the first ones by file name; the rest are dropped as normal safety drops, never refusing the job. Judge-side minor findings, keywords, non-attested sets and checks that did not run are unchanged, and the kept photos do not count toward the 90 % clear share. `gate.json` (`age_flags`) and `gate_trace.jsonl` (`kept_reasons`, `age_flag`, `age_flag_limit`) record the limit and which flagged photos were kept and dropped.
- Signed adult-verification record (`voxprint-lora-verify/1`, Canvas's SCHEMA): when the project's safety check passed and `gate.json` still matches the prepared files, Forge writes `<file name>.voxprint-verify.json` beside every saved checkpoint, exported `.safetensors`, `--install-to-mdl` copy and `.voxlora`. It has exactly the eleven signed fields `schema`, `record_id`, `lora_file`, `lora_sha256`, `project_id`, `dataset_image_count`, `age_gate_version` (`voxprint-lora-gate/1@5`), `verified`, `result`, `verified_at` and `algorithm`, plus `signature`: lower-case hex Ed25519 over their compact sorted-key JSON. The key is the install's raw 32-byte seed shared with Canvas, `$VOXPRINT_HOME/keys/lora-verify-ed25519.key` (0600 in a 0700 folder, created on first use, never printed, not the MDL index key); the record carries no public key. No record is written when the check did not pass; a signing failure after a pass is an error. `lora verify-record PATH` checks a record or the LoRA beside it against this install's key. `lora sign-checkpoints PROJECT` signs a project's existing checkpoints and refuses unless `gate_trace.jsonl` shows a kept photo and the gate passed with a current `gate.json`. `tools/forge_sign_lora.py` ports Canvas's reference signer. The safety check itself is unchanged.
- A LoRA trains on up to 500 photos in both modes: `lora.limits` `SIMPLE_CAP` and `EXPERT_CAP` are 500 (was 200), so Simple mode takes 10–500 and Expert mode warns outside 10–500, keeps the floor of 5 and now also caps at 500. The CLI help, the manual, the offline guide and the app strings follow the same constants.
- Test versions are vertical full-figure pictures drawn hotter (2026-11-16 owner decisions): default previews and review samples draw at the training resolution in a vertical 2:3 frame (`lora.preview_format.preview_size`, 1024 px -> 688x1024) with the LoRA at strength 1.3 (`lora.train.PREVIEW_LORA_SCALE`, applied through `lora.layers.lora_strength` only for the preview calls; training still runs at 1.0 and the saved weights are unchanged; the `voxprint.lora_scale` stamp and the `strength` metadata record 1.3). The default person prompt is `full-length vertical portrait, full figure from head to toe, standing, face clearly visible, looking at camera`, with `fully clothed in casual everyday clothes` for every person preview and `fully nude` as the second picture of an adult LoRA's pair (adult = the subject's `adult_generation` release answer when it is a boolean, else `adult_content`). Preview steps, `--preview-after`/`--preview-every` and the rank default are unchanged, and output stays WebP.
- Every LoRA export writes the trigger so Canvas can read it: `voxprint.subject.trigger` in the safetensors `__metadata__` (`lora export`, `lora finish` packages, the final train checkpoint, and a named `lora save-as` / `scripts/forge-save-as` copy such as `Tatiana_Model.safetensors`), and a top-level `"trigger"` string on the `voxprint-model.json` sidecar. Existing header keys, including the adult-generation line, are kept.
- The `balanced` preset trains 1600 steps (was 1500) in `PRESETS` and `TrainConfig`; rank and alpha stay 64. `scripts/forge-train --steps` already defaulted to 1600 and still does.

Flag values override the optional `<home>/model-forge/gui-defaults.json` (the same keys); the defaults preload the draft (crop, 18+/adult-content), the Expert panel (`lora.rank`, `lora.alpha` = rank, `lora.steps`) and the base picker, and `--photos DIR` loads that folder. `--help` and `--version` still print without Qt.
- The GUI records its photo folder for the terminal: picking a folder (Add a person's folder / Add a folder / a dropped folder) writes `<home>/model-forge/gui-selection.json`, removing every photo clears it, and `python -m voxprint_forge.app.launch --print-selection` prints the folder (exit 0) or "No photo folder selected…" on stderr (exit 3). `scripts/forge-train --photos-from-gui` trains on that folder, NAME defaults to the folder's name, and the helper's message stops the run on its non-zero exit.
- Release auto-detect: a `release.txt` directly inside a photo folder is read automatically — in the GUI (the person kind and the model name are preselected, the release is attached, complete consent ticks the consent/18+ boxes and the adult-content label, a status line names the file) and in `forge-train` (prints the file's sha256 and what it answers, takes NAME from it when the command line does not, turns `--adult-content` on for `Adult content in training: yes` unless `--no-adult-content` was given, and skips the consent/age prompts only when `Adult (18+)`, `Consent to training` and `LoRA training allowed` are all `yes`). The age/minors gate on prepare is unchanged and still fail-closed; `lora prepare` only lists image files, so the `.txt` is never read as a photo. Replaces the `release-adult-ok.txt` auto-detect, which is dropped.
- `lora prepare --release release.txt` (the GUI and `forge-train` pass it this way) parses the file and records `release_name`, `release_date`, `no_minors_attested`, `consent_generation`, `adult_generation` and `adult_content_training` on the `project.json` subject (missing lines stay `null`; older projects load unchanged). With `Adult (18+): yes` and `No minors in photos: yes` the captioner is told the subject is an adult and no minors are present, and a child word in a generated caption gets two re-captions, then is replaced by `adult`; only if the text is still dirty is that one frame dropped (`lora.drop.caption_keyword`). Without the attestation the rule-6 behaviour stays (one re-caption, then the frame is dropped). Every step is printed to stderr and listed in `project.json` `caption_fixes` (`recaptioned`/`replaced`/`dropped_frame`, with the match); `gate_run.json` records `no_minors_attested` and the fix count. `Adult content in training: no` leaves frames flagged unclothed out of training (`lora.drop.unclothed_release`). Export writes `voxprint.lora.adult_generation` and `voxprint.lora.consent_generation` to the safetensors header (`true`/`false`, `""` unknown) and the sidecar (`true`/`false`/`null`). The visual age gate is unchanged: the attestation never skips or weakens it.
- The window follows a command-line run started while it is open: every 2 s (while its own runner is idle and nothing is being followed) it scans the usual project roots for a project whose `project.json` is newer than the window and whose run is `running`, opens it once and follows it live on the Train step. It never starts, stops or otherwise touches the run.
- `lora prepare --crop both` is the default everywhere (CLI, GUI Draft, person presets and `scripts/forge-train`). Each kept photo prepares the whole frame as `{id}-full` and, when the safety gate found a face, a head-and-shoulders close-up as `{id}-close`; a photo without a face keeps the whole frame only and is never dropped for lacking a face. The stored captions carry one short framing word (`full body`, `close-up`). The gate, drop reasons and the photo hash stay tied to the source photo; the close-up reuses the gate's face box and is never gated twice. `subject` and `whole` remain Expert options, and the GUI's Simple flow uses `both` while hiding the crop chips (Expert shows all three, `both` selected).

- `lora prepare` photo I/O uses less memory: each photo is read from disk once (the photo id is hashed from the same bytes it is decoded from), decoded without extra full-size copies, and blur and duplicate checks share one grey copy. Kept photos are held as file bytes, not as decoded pixels. The PNG writes run on up to 4 threads, with results taken in input order. Prepared files, captions, `drops.jsonl` and `gate_trace.jsonl` are byte-identical to before, and the checks, the safety check and which photos are kept are unchanged. `scripts/bench_prepare_io.py` measures it. The Photos step's check and the Simple-mode count scan use the same single-read decode.
- `lora prepare` runs in phases: safety check with only the judge and age estimator loaded, a full unload (also when the check is interrupted), then the captioner. Photos are decoded one at a time per phase instead of all held decoded, which cuts peak RAM on large sets (`scripts/bench_prepare.py` measures it with CPU stand-in models). Each photo is cropped once (the caption uses the same crop that is written). Decisions, `gate_trace.jsonl`, `drops.jsonl`, captions and prepared PNGs are unchanged.
- `lora eval PROJECT [--step N|all] [--images DIR]`: likeness score with OpenCV YuNet + SFace (new optional MDL id `sface-2021dec`). Reference is the mean embedding of the kept training photos; the report gives each picture's cosine, mean, median, `n`, pictures with no face, and the training photos' own leave-one-out baseline. fail below 0.363, warn below 0.50 or below 0.6 x baseline. Written to `eval/likeness.jsonl`, `eval/report.json`/`report.md`, and `likeness` in `voxprint-model.json`. `lora finish` scores its final previews before export. Quality score only: it never blocks export and does not touch the safety check.

CLI errors name `voxprint-forge-cli models fetch` (or `accounts add` for upload tokens) instead of a window in the app.

- `lora prepare` appends each safety-check trace row and each safety drop as soon as the photo is decided, and writes `gate_run.json`. Training does not start while that run is `running` or `interrupted`; run prepare again. A photo with no trace row was not checked and is not set aside.
- `lora finish` on a straight-through run no longer leaves the project waiting in review when the checkpoint is missing or finish fails or is interrupted. Finish now builds the review state in memory and writes it to `review/state.json` only once the LoRA is saved, so `lora train` and `lora continue` still work afterwards. A missing checkpoint is now reported before finish fetches the base model.
- `lora prepare`: large single photos (for example 4500x3000 portraits) are no longer set aside as `lora.drop.collage`. Long straight edges inside one photo, such as a person against a backdrop or a floor line, were read as panel seams. Grids and side-by-side collages, with or without gutters, are still set aside.
- `lora prepare --keep FILE` (repeatable) keeps a photo that would be set aside as a collage or a near-duplicate. The photo still goes through every other check, the safety check included. docs/LORA.md and `--help` describe it.
- `lora prepare` keeps near-duplicate photos by default. A warning names the photo and the earlier photo it resembles. `--drop-near-duplicates` sets them aside as `lora.drop.duplicate` as before, and `--keep FILE` overrides that for one photo. A byte-identical copy of a photo is still skipped.
- `lora prepare`: captions describe attire as it appears. Unclothed subjects were sometimes described as wearing lingerie. Qwen3-VL's description prompts never asked about attire, and the separate unclothed answer never reached the caption text, so the model chose its own wording. Both description prompts now ask for the clothing as worn, or a plain neutral word (unclothed, nude, topless) when there is none, and ask the model not to name clothing that is not in the photo. Caption text is stored unchanged. The stored `unclothed` flag is now also true when the caption text says unclothed.
- `lora finish`: fixed "Expected all tensors to be on the same device, cuda:0 vs cpu" in the final preview. The preview loaded the base and the LoRA but never moved the transformer to the card (the adapters keep it on the CPU until the encoders are released), so the VAE and the prompt embeddings were on `cuda:0` and the transformer with its LoRA on the CPU. The final preview now follows the training order (encoders, prompts, encoders off, transformer and LoRA onto the card) and checks that the model is on one device first. `lora finish` also writes the `.voxlora` to `<project>/export/`. `--no-preview` skips the preview. A preview that fails prints `lora.warn.final_preview` and still finishes and exports the LoRA.
- `lora train` / `lora continue`: when a run pauses for review and stdin is not a terminal, a hint on stderr lists `lora review`, `lora continue` and `lora finish`, and `--review-rounds 0` for unattended runs. The GUI is unchanged.
- `--sample-framing {mixed,portrait}` on `lora train` and `lora continue` (stored as `sample_framing`). `portrait` draws every review sample as a face close-up for judging likeness. The default `mixed` is the old rotation. `lora continue` also takes `--sample-attire`.
- Docs and help: use `--preset balanced` for a person LoRA; `quick` is a smoke test (RTX 4090 person run: quick 120 steps 1.68/5 likeness, balanced 1000 steps 3.95/5). Only the exported `.voxlora` is the deliverable; `checkpoints/step-*.safetensors` are intermediate and Canvas does not accept them.
- lora gate: primary-face selection (gate.json v-bump).
- `lora prepare`: `drops.jsonl` has one line per set-aside photo. A re-run on the same project no longer appends a second copy of earlier lines.
- Windows setup: adds `{app}\venv\Scripts` (`voxprint-forge-cli.exe`) to the current user's `Path` once, and the uninstaller removes only that entry. The old RU guide shortcut is now removed by an ASCII pattern.
- `preflight` and the other plan commands work on an installed copy without a checkout: the default plan ships in the package (`voxprint_forge/data/plan.toml`, kept equal to `plans/plan.toml` by a test). A checkout's `plans/plan.toml` and an explicit `--plan` still take precedence.
- `lora prepare --help` explains `--name` and `--consent-method` and shows an example. A missing `--name` prints one line with an example, `--name Garnis_AI --consent-method verbal` (still exit 2). docs/LORA.md documents `--name`, `--consent-method` and `--fetch-missing`.

Linux from-source install: `installer/linux/install.sh` installs the `[gui]` extra, the pinned MiVOLO package (commit `37475e3f8818b5f22448003feec3e64b01bfb188`, `--no-deps --no-build-isolation`, `setuptools<81`), and writes `~/.local/share/applications/voxprint-model-forge.desktop` with the app icon. When the age estimator does not load because those packages are missing, `lora prepare`/refset fail closed with `lora.err.gate_missing_deps`, which names that install command instead of the misleading "Prepare the photos first".
- App: the "Extend the set from samples" switch on the Photos step, the overflow-menu "Add more photos to a model…" action and the result-step "Add more photos" button are hidden for now; the implementation stays behind `EXTEND_FROM_SAMPLES_ENABLED = False` in `voxprint_forge.app.window` and comes back later as its own task. The `lora extend` and `lora refset` commands are unchanged.
